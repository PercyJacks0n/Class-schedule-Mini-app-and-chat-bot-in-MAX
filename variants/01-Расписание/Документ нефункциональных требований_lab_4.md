## 2. Группы из названия работы

| Группа | Где закрыта | Основание |
|--------|-------------|-----------|
| Аутентификация | НФТ-3, авторизация диспетчеров Учебного управления по сессионному JWT-токену | Диспетчеры входят по корпоративным учетным записям. Студенты и преподаватели в MAX подтверждают личность своим аккаунтом в мессенджере (отдельный пароль для бота не требуется) |
| Авторизация | НФТ-3, ролевая модель доступа | Диспетчер имеет права на просмотр, изменение расписания и публикацию. Студент и преподаватель имеют права только на чтение своего расписания и настройку подписок в MAX |
| Структуры хранения | Локальная реляционная база данных PostgreSQL (таблицы расписания, журнала аудита, подписок); НФТ-4 запрещает создание дублирующих справочников | Собственные данные системы хранятся в PostgreSQL. Справочники кафедр, сотрудников и аудиторий читаются из 1С и кэшируются, повторный ввод запрещен |
| Политики защиты | НФТ-4, защита исходных данных 1С и сетевого периметра | Запрет на запись в 1С исключает порчу учебных планов и кадровых данных. Все внешние вызовы шифруются по HTTPS/TLS 1.3. Токен доступа к Bot API MAX хранится в переменных окружения |
| Развертывание | Серверная инфраструктура университета, контейнеры Docker, НФТ-7 | Система развертывается в виде Docker-контейнеров (веб-интерфейс, бэкенд API, PostgreSQL) на локальном сервере университета. Запуск зависит от сетевой доступности сервера 1С и шлюза MAX |
| Эксплуатация | НФТ-5, НФТ-8, мониторинг доступности и журнал ошибок | Контроль состояния через health-check эндпоинт `/health`. Сбои сетевого шлюза 1С или сервиса MAX не приводят к падению системы, а фиксируются в журнале аудита |
| Протоколы | НФТ-6: 1С:Университет ПРОФ по HTTP REST GET, Bot API мессенджера MAX по HTTPS REST POST | Вызовы зафиксированы в контрактах КНТ-1 и КНТ-2. Другие протоколы (SOAP, gRPC) не используются, так как смежные системы их не требуют |
| Потоки данных | 1С:Университет ПРОФ -> Сервер расписания -> База PostgreSQL -> Bot API MAX -> Студенты и преподаватели | Схема потоков зафиксирована в `diagrams/landscape.puml`, вызовы детализированы в `sequence-1c.puml` и `sequence-max.puml` |
| Балансировка нагрузки | НФТ-7, архитектура без сохранения состояния сессий в памяти (stateless) | Отдельный специализированный балансировщик не разрабатывается: используется стандартный обратный прокси Nginx. Требование к сервису - возможность работы в нескольких экземплярах |

## 4. Приоритет нефункциональных требований

| ID | Приоритет MoSCoW | Обоснование |
|----|------------------|-------------|
| НФТ-2 | Must | Без автоматической быстрой проверки накладок преподавателей и аудиторий теряется главный смысл системы: диспетчер не сможет оперативно составлять расписание без ошибок |
| НФТ-3 | Must | Неавторизованный доступ к изменению расписания недопустим: любой посторонний пользователь мог бы сорвать учебный процесс университета |
| НФТ-4 | Must | Прямое изменение справочников в 1С из внешней системы строго запрещено регламентом ИТ-отдела: нарушение этого правила приведет к порче кадрового и учебного учета |
| НФТ-5 | Must | Сеть между корпусами или сервер 1С могут временно отключаться; система расписания не должна останавливать работу диспетчеров и студентов при сбоях внешнего шлюза |
| НФТ-6 | Must | Без строгого соблюдения форматов вызовов к 1С и MAX интеграция не заработает, функции импорта и оповещения будет невозможно принять |
| НФТ-1 | Should | Быстрое открытие сетки (до 1.5 с) важно для удобства диспетчера, но небольшое превышение на этапе опытной эксплуатации не блокирует сам процесс согласования |
| НФТ-7 | Should | На этапе пилота сервис может работать в одном экземпляре, однако отсутствие сохранения сессий в памяти обязательно закладывается в архитектуру для масштабирования |
| НФТ-8 | Should | Журнал аудита необходим для разбора спорных ситуаций по переносам пар; порог фиксации 0.5 с обеспечивает прозрачность действий без задержки интерфейса |
| НФТ-9 | Should | Доставка уведомлений за 30 с гарантирует оперативность оповещения; при высокой нагрузке на шлюз MAX допустима небольшая очередь отправки |
| НФТ-10 | Could | Ограничение в 3 клика повышает удобство работы студентов в боте MAX, но не блокирует техническую возможность получения расписания текстовой командой |
